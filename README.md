# اسرار ازل

نسخهٔ آزمایشی: https://miadjaberi.github.io/asrar-azal-test/

## مرز پروژه و اصول ثابت
- این مخزن فقط برای توسعه و آزمایش اسرار ازل است؛ مخزن اصلی اسرار ازل و مخزن کافه سرکتاب میعاد نباید در جریان توسعه تغییر کنند.
- اسرار ازل فقط آنلاین است. Service Worker صرفاً درخواست‌ها را به شبکه می‌فرستد و کش یا جایگزین آفلاین ندارد.
- طراحی، چیدمان، متن‌ها، مودال‌ها و منطق بومی اسرار ازل حفظ می‌شوند؛ ساختار کافه فقط مرجع استخراج الگوهای فنی و قابلیت‌های موردنیاز است.
- هیچ دادهٔ واقعی کاربران، حساب‌ها، PINها، سوابق، پیام‌ها، سفارش‌ها، اشتراک‌ها یا اطلاعات خصوصی کافه به اسرار ازل منتقل نمی‌شود. فقط ساختار و منطق لازم، پس از تطبیق، بازسازی می‌شود.
- هر سرنخ باید در رابط کاربری، منطق برنامه، Supabase، امنیت و آزمون سرتاسری تکمیل و ثبت شود؛ سپس با تأیید کاربر سراغ سرنخ بعدی می‌رویم.

## احراز هویت؛ الگوی مرجع
- حساب کاربر: شماره تلفن + PIN هشت تا دوازده رقمی؛ مسیر ثبت‌نام/ورود باید در سرور کنترل و rate-limit شود.
- مدیر: مسیر مستقل OTP تلگرام/Supabase Auth؛ ورود مدیر نباید با مسیر PIN کاربران ادغام شود.
- سورس Edge Function با نام `phone-pin-auth` در مخزن وجود دارد، اما در آخرین بررسی هنوز روی Supabase deploy نشده بود؛ بنابراین ورود شماره/PIN هنوز عملیاتی و تأییدشده نیست.
- UI واقعی حساب کاربری هنوز باید در اسرار ازل پیاده‌سازی و به پروفایل و session وصل شود. صفحهٔ فعلی `prof` صرفاً placeholder است.
- ماژول `asrar-commerce.js` در حال حاضر یک Supabase client جدا می‌سازد و برای مدیر prompt ایمیل/رمز دارد؛ پیش از اتصال نهایی باید با یک client/session مشترک و مسیر OTP مستقل مدیر یکپارچه شود.

شمارش تجمیعی جدول‌های حساب و تراکنش در پروژهٔ آزمایشی در ۲۵ نوامبر ۲۰۲۶:
- profiles: 0
- orders: 0
- support threads: 0
- support messages: 0
- subscription requests: 0
- user subscriptions: 0

هیچ دادهٔ کاربری یا تراکنشی از کافه به این پروژه منتقل نشده است. این شمارش فقط وضعیت لحظهٔ بررسی را نشان می‌دهد و ممکن است با ثبت دادهٔ آزمایشی تغییر کند.

## امنیت و آزمون
- آخرین Security Advisor در ۲۵ نوامبر ۲۰۲۶ بدون finding برگشت.
- Performance Advisor هشدارهایی دربارهٔ شاخص برخی foreign keyها، ارزیابی مجدد بعضی توابع RLS و policyهای permissive چندگانه گزارش کرده است؛ این موارد باید در مرحلهٔ بهینه‌سازی بررسی شوند.
- وجود migration یا کد به معنی فعال‌بودن قابلیت نیست. هر قابلیت تا زمان آزمون واقعی مرورگر و سرور «تکمیل‌شده» محسوب نمی‌شود.
- کلید service_role/secret فقط در محیط امن سمت سرور/Edge Function مجاز است و هرگز نباید در HTML، JavaScript یا GitHub Pages قرار بگیرد.

## PWA
- Manifest و Service Worker برای نصب‌پذیری حفظ شده‌اند.
- Service Worker فقط درخواست شبکه را عبور می‌دهد؛ هیچ cache، offline fallback یا قابلیت آفلاین در محدودهٔ پروژه نیست.

## ترتیب بستن سرنخ‌ها
1. حساب کاربری، هویت آنلاین، پروفایل و تنظیمات حساب.

3. سوابق سفارش/اشتراک و اتصال یکپارچه به حساب.
4. داشبورد مدیریت، فروشگاه، سفارش، اشتراک، پرداخت و تخفیف؛ آزمون انتها‌به‌انتها.
5. مدیریت محتوا، مودال‌ها، ظاهر و هویت بصری؛ آزمون واقعی آپلود و ذخیره.
6. امنیت، کنترل‌های فنی، کارایی، تست موبایل/دسکتاپ و آمادگی انتشار.
