## قرارداد فعلی Edge Function کاربر

ورودی POST:
- `action`: فقط `register` یا `login`
- `phone`: الگوی شماره موبایل ایران با ۱۱ رقم و شروع `09`
- `pin`: ۸ تا ۱۲ رقم
- `name`: برای ثبت‌نام الزامی، حداکثر ۱۰۰ نویسه

رفتار:
- ساخت ایمیل داخلی بر اساس شماره با دامنه `.invalid`.
- استفاده از service role فقط داخل Edge Function برای ساخت حساب و ثبت پروفایل.
- ورود با Supabase Auth و رمز PIN؛ خود Auth مسئول hash رمز است.
- rate limit با کلید hashشده شماره و IP؛ ۸ تلاش شماره و ۳۰ تلاش IP در پنجره ۱۵ دقیقه‌ای.
- در پاسخ موفق، `session` و داده پروفایل برگردانده می‌شود؛ کلاینت باید با `auth.setSession` نشست را در client مشترک برقرار کند.
- تابع باید برای درخواست عمومی ثبت‌نام/ورود قابل فراخوانی باشد؛ بنابراین verify_jwt در deploy باید متناسب با همین قرارداد تنظیم شود و خود تابع کنترل اعتبار شماره/PIN و rate limit را انجام دهد.

## مواردی که پیش از deploy/تست باید اصلاح یا تعیین تکلیف شوند

1. **حساب یتیم در ثبت‌نام:** اگر ساخت Auth user موفق و insert در `profiles` ناموفق شود، تابع فعلی حساب Auth را حذف نمی‌کند. باید rollback/cleanup امن اضافه شود یا وضعیت بازیابی مشخصی داشته باشد.
2. **CORS باز:** `Access-Control-Allow-Origin: *` است. برای سایت ثابت فعلی بهتر است به origin رسمی اسرار ازل محدود شود و preflight نیز همان origin را برگرداند.
3. **ویرایش پروفایل:** policy و grant فعلی به کاربر اجازه ویرایش نام خودش را نمی‌دهد؛ update فقط مدیر است. برای امکان ویرایش نام باید مجوز ستونی/تابع امن طراحی شود، بدون امکان تغییر phone یا role توسط کاربر.
4. **آخرین ورود:** ستون `last_login_at` در جدول فعلی وجود ندارد. باید مشخص شود با trigger امن یا به‌روزرسانی سمت سرور ثبت شود؛ از کلاینت نباید قابل جعل باشد.
5. **کد کاربری:** هنوز معلوم نیست کافه از چه قالبی برای کد کاربری استفاده می‌کند؛ UUID خام یا کد ساختگی نباید بدون بررسی به‌عنوان قرارداد انتخاب شود.
6. **نشست واحد:** پیش از استفاده از تابع باید client واحد ایجاد شود؛ client دوم در commerce حذف و همه ماژول‌ها از همان session استفاده کنند.
7. **OTP مدیر:** تابع/قرارداد OTP مدیر در اسرار ازل وجود ندارد و پیاده‌سازی اجرایی کافه هم در دسترس این بررسی نبود. تا تعیین قرارداد، ورود مدیر با prompt ایمیل/رمز نباید به‌عنوان مسیر نهایی باقی بماند؛ اما نباید با حدس جایگزین شود.
